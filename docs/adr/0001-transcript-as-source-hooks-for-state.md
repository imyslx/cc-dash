# ADR-0001: 本体データは会話記録から読み、フックは状態変化だけを記録する

- 状態: 採用
- 日付: 2026-11-25

## 背景

ダッシュボードには、時系列（依頼・途中メッセージ・ツール呼び出し）と、「誰の番か」の両方が必要。

Claude Code は各セッションの会話記録を `~/.claude/projects/<project>/<session>.jsonl` に書き出しており、フックにもそのパス（`transcript_path`）が渡される。一方で、許可待ちのように**会話記録が増えないまま状態が変わる**場面がある。

## 検討した案

1. フックで全部のデータを自前の JSONL に書き出す
2. 会話記録だけを読み、状態も推定する
3. 会話記録を本体にし、会話記録に残らない状態変化だけをフックで記録する

## 決定

案3を採用する。

- 時系列・途中メッセージ・Todo・ツール呼び出しは会話記録から読む
- フック（`hooks/hook.mjs`）は `SessionStart` / `UserPromptSubmit` / `Notification` / `Stop` / `SessionEnd` だけを `~/.cc-dash/events.jsonl` に追記する
- フックは追記以外の処理をしない。失敗しても必ず exit 0 で抜ける

## 理由

- 案1は会話記録と同じ情報を二重に持つことになり、フックが重くなる。フックが遅いと Claude Code 本体が待たされる
- 案2は許可待ちを検出できない（記事でも同じ問題があり、フックで解決していた）
- 案3なら、フック導入前のセッションも会話記録から推定で表示できる

## 影響

- 会話記録の形式は公開された安定 API ではないため、Claude Code の更新で読み方の修正が要ることがある。読めない行は捨てて動き続ける作りにする
- イベントログは追記専用なので、ダッシュボードが止まっていても後から状態を復元できる
