# ADR-0002: 状態の札は「誰の番か」で決める

- 状態: 採用
- 日付: 2026-11-25

## 背景

並列で走らせているときに知りたいのは「どれに自分が手を入れるべきか」。経過時間で札を分けると、長く待たせている返事待ちが「止まっている」と同じ扱いになり、自分の番なのか Claude の番なのかが分からなくなる（参考にした記事と同じ考え方）。

## 決定

札は次の5つ。判定は `src/status.mjs`。

| 札 | 誰の番 | 判定 |
| --- | --- | --- |
| 返事待ち | 自分 | 今回の依頼より後に `Stop` が来た（裏で動かしたサブエージェントの報告待ちを除く）／許可の確認が出たあと会話記録が増えていない／中断した |
| 作業中 | Claude | 上記以外で、直近3分以内に会話記録が増えている。または、`Stop` のあとでも裏で動かしたサブエージェントの報告を待っている |
| 止まっている | Claude | Claude の番なのに3分以上動きがない |
| 区切り | — | 6時間以上触っていない |
| 終了 | — | `SessionEnd` を受け取った |

- 返事待ちが長く続いても「止まっている」には移さない。代わりに、30分を超えたら待ち時間を赤く表示する
- 返事待ちには理由（返答／許可待ち／中断）を添える
- フックがないセッションは、保留中のツール呼び出しと最後の発言者から推定する
- 裏で動かしたサブエージェント（`Agent` ツールの結果が「Async agent launched」）の報告を待っている間は、「作業中・サブエージェント」とする。報告が届くと Claude が続きを始めるので、自分の番ではない。待っている間は親の会話記録が動かないので、「止まっている」には移さない。報告が来ないまま終わるサブエージェントもあるため、起動から60分を過ぎたら待たない（実測では起動から報告まで最大28分）。裏で動かした `Bash` は、終わらない常駐もあるので数えない

## 影響

- 許可待ちの判定は `Notification`（`permission_prompt` / `elicitation_dialog`）に依存する
- しきい値は `src/config.mjs` で変えられる
