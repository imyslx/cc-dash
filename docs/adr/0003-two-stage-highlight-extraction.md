# ADR-0003: 大事なことの抽出はルール → Haiku の2段構えにする

- 状態: 採用
- 日付: 2026-11-25

## 背景

このツールの一番の目的は、途中メッセージから流れていった大事なことを拾うこと。拾う対象は5種類に決めた。

| 種類 | 例 |
| --- | --- |
| 仮定（assumption） | 「仕様にないので TTL は5分にしました」 |
| スキップ（skip） | 「E2E テストは環境の都合で未実行です」 |
| 懸念（risk） | 「本番の値を参照しないよう注意が必要です」 |
| 確認（question） | 「在庫0件のときもキャッシュしますか？」 |
| 発見（discovery） | 「同じクエリが3回呼ばれていることが分かりました」 |

特に「仮定」と「スキップ」は最後の返答のまとめから落ちやすく、レビューで一番見たいもの。

## 検討した案

1. ルール（正規表現）だけ
2. 全メッセージを LLM で分類
3. ルールで常に拾い、LLM は任意で上書き

## 決定

案3を採用する。

- 1段目（`src/highlights.mjs`）：文単位でキーワードを当て、最初に当たった種類を付ける。コードブロックの中は見ない。常に動く
- 2段目（`src/llm.mjs`、`CC_DASH_LLM=1` のときだけ）：途中メッセージを `claude -p --model haiku` に渡し、JSON 配列で分類させる。結果があればルールの結果を置き換える

## 理由

- ルールだけでも、外部呼び出しなしで即座に動き、それなりに拾える
- LLM は精度が上がるが、呼び出しの手間と待ち時間がかかる。常に必須にはしたくない
- ローカルの `claude` CLI を使えば、API キーの管理が要らない

## 注意点

- ダッシュボードが `claude -p` を呼ぶと、その呼び出し自体が新しいセッションとして会話記録に残り、フックも動く。これを避けるため、
  - 専用ディレクトリ（`~/.cc-dash/llm-workdir`）を作業ディレクトリにして、そこのセッションは一覧から除く
  - 環境変数 `CC_DASH_INTERNAL=1` を渡し、`hook.mjs` は何も記録せずに抜ける
- 呼び出し回数を抑えるため、本文のハッシュでキャッシュし、起動時にさかのぼるのは直近24時間分だけにする。並列数は1

## 影響

- ルールの語句は日本語と英語の両方を持つ。誤検出・取りこぼしは運用しながら `RULES` を育てる
