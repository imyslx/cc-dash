# ADR-0005: 複数端末は Tailscale 内の pull 型で集約する

- 状態: 採用
- 日付: 2026-11-25
- ADR-0004 の「127.0.0.1 だけで待ち受ける」を一部置き換える

## 背景

Claude Code を2台で使っている。

- **Windows（メイン）**：VS Code 拡張で設計作業。いつも見ている画面はこっち
- **Mac**：実装作業

どちらのセッションも、Windows の1画面で見たい。返事待ちの通知も Windows で受け取りたい。

## 検討した案

1. **pull 型**：各端末で cc-dash を動かし（エージェント）、1台（ハブ）がほかの端末の API を取りに行く
2. **push 型**：各端末がハブに状態を送る
3. **同期フォルダ**：Syncthing や iCloud などで会話記録を共有し、ハブが全部読む
4. **クラウドに集約**：外部のサーバーに各端末から送る

## 決定

案1を採用する。Windows をハブ、Mac をエージェントにする。

- エージェントは今の cc-dash そのもの。既存の `/api/sessions`・`/api/sessions/:id`・`/api/stream` をそのまま使う
- ハブは `~/.cc-dash/peers.json` に書いた相手の SSE を購読し、変更が来たら一覧を取り直してまとめる（`src/peers.mjs`、`src/merge.mjs`）。詳細は中継する
- 別端末のセッションのキーは `<端末名>::<セッションID>`
- 通信は Tailscale の中だけ。エージェントは Tailscale の IP だけで待ち受ける（`CC_DASH_HOST`）
- ループバック以外からのアクセスにはトークンを必須にする（`CC_DASH_TOKEN`、`src/auth.mjs`）。ループバック以外で待ち受けるのにトークンがなければ起動しない
- 通知音はハブ（Windows）のブラウザで鳴らす。Haiku 分類は各エージェントで行い、ハブは結果を受け取るだけ

## 理由

- 案1は、すでにある API を使うだけで、追加するのはハブ側の集約だけ
- 案2はハブが止まっている間の再送や順序の扱いが要る。NAT の内側の端末が多い場合には有利だが、Tailscale があれば不要
- 案3は、追記中の大きな JSONL を同期すると壊れやすく、差分読みのオフセットとも相性が悪い
- 案4は便利だが、顧客案件のコードを含む会話記録の要約が外に出る

## 影響

- 会話記録の中身は各端末に置いたまま。ハブに流れるのは一覧と、開いたセッションの詳細だけ
- Mac がスリープすると接続が切れる。ハブは60秒 SSE に何も来なければ切れたとみなし、「オフライン（最終確認の時刻）」として最後の状態を薄く残す。オフライン端末の分は件数と通知から外す
- 端末間の時計のずれは、一覧を取ったときの相手の `now` との差で補正する
- VSCode ボタンは、別端末のセッションなら `peers.json` の `ssh` を使って Remote-SSH で開く。`ssh` がなければボタンを出さない
- Windows 対応のための修正も合わせて入れた（`claude.cmd` の起動、パスの区切り、フックのコマンドの書き方、npm スクリプトの環境変数）
